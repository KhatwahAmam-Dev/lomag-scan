Berikut perancangan teknis untuk menyesuaikan alur baru tersebut: 1. Struktur Data Master & Hasil Scan Agar mendukung lokasi rak dan pembaruan data secara langsung (real-time), struktur datanya kita bagi dua: Data Master (JSON): Tersimpan di penyimpanan lokal (local storage/IndexedDB). Jika ada barang baru diinput manual, sistem langsung menyuntikkan data baru tersebut ke master JSON ini. JSON { "899123456789": { "nama": "Kopi Susu 200ml", "deskripsi": "Kopi kemasan botol", "kategori": "Minuman" } } Data Hasil Scan (Per Sesi Opname): Menyimpan detail jumlah barang beserta lokasi raknya untuk kebutuhan kroscek checker. JSON [ { "barcode": "899123456789", "kode_rak": "RAK-A-01", "qty": 5, "last_scanned": "2026-09-20 20:00:00" } ] 2. Logika Pemindaian & Batch Scanning Set Kode Rak: Sebelum mulai scan, operator memasukkan/memilih Kode Rak yang sedang dikerjakan (contoh: RAK-A-01). Proses Scan: Sudah ada di rak yang sama: Nilai qty otomatis bertambah (qty + 1). Barang terselip (scan ulang di rak lain): Sistem mencatatnya sebagai entri baru khusus untuk RAK-B-02. Checker bisa dengan mudah melacak di rak mana saja barang tersebut tersebar. Belum terdaftar: Muncul pop-up input manual, tersimpan ke master JSON, lalu otomatis masuk ke hitungan rak aktif. 3. Indikator Audio (Umpan Balik Suara) Untuk efisiensi kerja di lapangan, kita gunakan tiga jenis nada beep sederhana: Beep Tinggi (1x): Scan berhasil dan barang terdaftar. Beep Ganda (2x): Barang berhasil di-scan ulang (Qty bertambah dalam mode batch). Beep Rendah/Peringatan: Barang belum terdaftar di data master (memicu pop-up input manual). 4. Format Ekspor PDF & Excel Laporan ekspor nantinya memiliki dua pilihan tampilan: Mode Rekap Per Rak: Mengelompokkan barang berdasarkan nomor rak agar checker mudah melakukan audit fisik titik demi titik. Mode Rekap Total: Menjumlahkan seluruh qty dari semua rak menjadi satu total barang. Di lembar PDF, setiap baris memuat Gambar Barcode, Kode Rak, Deskripsi Produk, dan Total Qty.
